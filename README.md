# Poke'Catch 挂机助手 · AutoFarm

针对 `https://pokecatch-online.netlify.app/` 的油猴脚本（Tampermonkey / Violentmonkey）。

游戏本身是放置玩法：队伍沿路线自动前进、自动战斗、自动捕获。**它真正卡住的地方不是战斗，而是"需要你点一下"的瞬间** —— 捕获新宝可梦会弹图鉴卡、进化会播过场动画、章节切换会出确认框，只要不点，整条冒险就停在原地。这个脚本解决的就是这些。

---

## 一、脚本做了什么

### 1. 解除挂机阻塞（核心）

| 阻塞点 | 游戏表现 | 脚本处理 |
| --- | --- | --- |
| 捕获图鉴卡 | 抓到新宝可梦弹全屏卡，"继续"不点就一直停 | 自动点「继续」 |
| 进化过场 | 播放动画 + "点击继续"，等玩家点 | 自动跳过 |
| 普通确认弹窗 | 存档/道具/提示类弹窗 | 安全白名单内自动确认 |
| 礼物 / 单选弹窗 | 需要先选一个再确认 | 自动选第一个并确认 |
| 地图上的道具 / 化石选择 | "选择一块化石吧" 这类悬浮选择框 | 自动选第一个并确认 |
| 标题画面 | 刷新后停在"继续"按钮 | 自动进入游戏 |
| 战斗速度 | 默认 ×1 | 自动切 ×3 并持续保持 |

> 安全边界：
> 1. 只点白名单按钮（继续 / 确定 / 太棒了 / Continuer / Fermer …）。
> 2. 弹窗文字里出现 **放生 / Relâcher / 出售 / 删除 / 重置 / 放弃 / 改名** 等不可逆操作词时，整个弹窗**一个按钮都不点**（放生确认框、详情卡都在此列）。
> 3. 你一旦真的动了鼠标或键盘（`isTrusted` 的真实事件），脚本立刻让路 2.5–8 秒，绝不和你抢操作；这段时间也不会误报"停滞"。
> 4. 无法识别的弹窗不动它，只在面板报警提醒你。

### 2. 收益与操作优化

- **自动进化**：`全部进化` 按钮出现可进化的数字时自动点，带失败退避（连续无效会把间隔指数拉长，避免反复弹窗）。
- **定时保存**：默认每 5 分钟点一次保存。
- **自动进入游戏**：刷新 / 掉线回来后自动点「继续」，挂机不中断。

### 3. 实时面板（右上角，可拖动、可折叠）

- 当前速度、章节与节点进度、图鉴数、队伍与库存
- **捕获 /时、战斗 /时、金钱 /时**（近 90 秒滑动窗口，比整数总量更直观）
- 闪光计数、无进展秒数、最近事件日志
- 「暂停 / 继续」与「诊断」（诊断会把当前状态 JSON 复制到剪贴板，便于排查）

### 4. 提醒与保护

- **闪光提醒**：扫描到新闪光（含培育屋里的）→ 提示音 + 桌面通知 + 日志
- **徽章提醒**：拿到新徽章时提醒
- **限时活动提醒**：检测到传说活动 / 特殊区域开启时提醒
- **停滞检测**：用存档 `lastTick` 判断游戏世界是否还在走；超过阈值（默认 120 秒）报警，可开启"自动刷新"
- **屏幕常亮**：Screen Wake Lock，防止系统休眠打断挂机
- 窗口切到后台时明确提示"游戏已暂停"

### 5. 与你的操作共存

- 你点开任意宝可梦详情卡时，脚本识别为"玩家查看态"，不会去点卡片里的任何按钮，也不会弹警告。
- 详情卡里点"放生"弹出的确认框，脚本全程不碰，取消/确认都由你决定。
- 你手动调速度后 8 秒内脚本不会把速度抢回去。

### 5. 快捷键

| 键 | 作用 |
| --- | --- |
| `Alt + P` | 暂停 / 继续自动化 |
| `Alt + H` | 显示 / 隐藏面板 |

## 二、安装

1. 浏览器安装 **Tampermonkey**（或 Violentmonkey）。
2. 打开 Tampermonkey 面板 → **添加新脚本**，把 `pokecatch-helper.user.js` 全文粘贴进去，保存。
3. 打开 <https://pokecatch-online.netlify.app/>，右上角出现「挂机中」面板即成功。
4. 点面板右上 ⚙ 可以逐项开关。

脚本匹配两个域名：

```
https://pokecatch-online.netlify.app/*
https://pokecatch-online.pages.dev/*
```

配置存在 `localStorage['pcauto.cfg.v1']`，闪光记录存在 `pcauto.shinies.v1`，不会碰游戏自己的存档 `gachamon-save-v1`。

## 三·五、为什么"挂了一夜却没抓到夜间宝可梦"

源码里的昼夜判定（`t.DAYTIME`）：

| 相位 | 时间（浏览器本地时区） |
| --- | --- |
| 🌅 早晨 | 08:00 – 09:59 |
| ☀️ 白天 | 10:00 – 19:59 |
| 🌙 夜晚 | 20:00 – 次日 07:59 |

夜间有几套专属规则，例如 `CONDITIONAL_WILD`：草原夜晚追加咕咕/走路草并踢掉波波、烈雀；森林夜晚追加鬼斯/圆丝蛛/咕咕并把绿毛虫、独角虫整族从池子里移除。所以夜里"没刷到夜间怪"绝不会是概率问题，一定是下面三条之一：

**① 页面在后台时，游戏是彻底停摆的（实测）**

主循环第一行就是 `if (document.hidden) { await visibilitychange; continue; }`。

实测（切到别的标签页 60 秒）：

```
切走前 lastTick = 1793771830536
60 秒后 lastTick = 1793771830536   ← 一秒都没动
捕获 267 → 267，战斗 522 → 522
```

**② 回到前台时才补算，而补算用的是"回来那一刻"的时段**

同一个实验里切回来 6 秒后，`lastTick` 一次跳了 62 秒把空白补上 —— 但 `Daytime.index()` 读的是 `new Date().getHours()`，即**当前时刻**。所以：

> 晚上 23:00 挂机、页面在后台 → 整夜停摆 → 早上 7:00 回来 → 补算 8 小时，全部按"早上"的权重结算。
> 夜间权重的那部分时间，从来没有被真正执行过。

这也是为什么"退出也会自动八小时"给了你错觉：那 8 小时是按你回来的时段一次性补的，不是按夜里。

**③ 室内场景昼夜权重直接失效**

`Daytime.weight()` 里：场景属于室内（洞穴、道馆、宝可梦中心、月见山、岩山隧道、双子岛、华蓝洞、地下通道……）时，直接返回 `Math.max(...权重)`，**完全不看时段**。所以哪怕整夜在前台，只要队伍在洞里，夜间限定也不会出现。

脚本现在会直接把这个状态标在面板上：`室内·昼夜无效` / `室外·昼夜生效`。

## 三·六、整夜挂机的正确姿势

1. **用一个独立窗口放游戏，不要最小化、不要切标签页**（窗口被其他窗口挡住没关系，只有最小化/切标签/锁屏才会 hidden）。
2. 系统电源里关掉"睡眠"，屏幕可以关（关屏不等于锁屏；macOS 合盖会睡、Windows 睡眠也会停）。
3. 面板开「保持屏幕常亮」+「后台保活」兜底。
4. 睡前看一眼面板：`室外·昼夜生效` 才是有效的夜间挂机场景；`室内·昼夜无效` 的话换个室外路线再睡。
5. 看「夜间捕获」这一行 —— 夜里它一直是 0 就说明没在跑。

> 后台保活的实测边界：勾选后切走，标签页确实继续推进（60 秒实测推进 9–53 秒，取决于浏览器节流阶段）。Chrome 对后台标签有分阶段节流（前 5 分钟约 1 秒/次，之后可能降到 1 次/分钟），脚本用一路近乎无声的音频把标签标记为"有音频输出"来缓解，但**不能保证满速**。真正的满速只有一个办法：窗口可见。

## 三·七、消耗品自动化与对战优化

### 树果增益（自动）

游戏里真正"需要你主动吃"的消耗品是树果 —— 每颗给一个 family 的限时增益，`BUFF_MIN=60` 分钟，最多叠 4 层（240 分钟）。脚本会自动维持：

| 树果 | 增益 | 倍率 |
| --- | --- | --- |
| 星桃果 starf-berry | 闪光率 | ×2 |
| 谜之果 enigma-berry | 图鉴（未收录） | ×3 |
| 芭娜娜果 nanab-berry | 稀有遇敌 | ×2 |
| 金蔓莓果 golden-razz-berry | 捕获率 | ×1.5 |
| 蔓莓果 razz-berry | 捕获率 | ×1.25 |
| 凤梨果 pinap-berry | 经验 | ×1.25 |
| 兰萨果 lansat-berry | 金钱 | ×1.25 |

规则（都对齐了游戏的判定，不会白吃）：

- 剩余时间 ≥ 「补一颗阈值」（默认 25 分钟）就不吃；
- 每种树果每分钟最多吃一颗，避免连点；
- 每种保留「保留数」（默认 1 颗）不吃，方便你手动留底；
- 同族已有更高阶增益（如金蔓莓果 vs 蔓莓果）且还够用时，不吃低阶去覆盖；
- 快到叠加上限时自动停手（游戏本身也会拒绝）；
- **不触发「替换你的树果？」弹窗**：同族已有更高阶增益（金蔓莓果 rank2 > 蔓莓果 rank1）时，一律不吃低阶，等它自然过期 —— 这个弹窗的唯一来源就是"低阶顶替高阶"，从源头掐掉。
- 万一弹窗还是出现了：脚本自己发起的 → 自动点「替换」；不是脚本发起的（你自己点的）→ **给你 10 秒自己选**，超时才自动点「保留」关闭，不会把你卡在弹窗里。

面板顶部会显示当前增益与剩余分钟，剩余 ≤5 分钟标黄。

### 经验糖果（一键喂，不做全自动）

喂糖必须逐只打开宝可梦详情卡点按钮，游戏没有批量入口。让它全自动的话，会每几分钟把界面从冒险切到队伍、连开 6 张卡再关掉 —— **这会打断挂机节奏，还会和你的操作抢界面**。所以做成设置面板里的「一键喂经验糖」：你点一下，脚本按「大糖优先」依次喂队伍里所有未满级成员，喂完自动切回冒险页。

> 全队到达本章等级上限时，糖果按钮本身是 disabled 的，脚本会直接提示「没有可喂的目标」，不会空转消耗。

### 对战逻辑：能优化什么

先说结论：**这个游戏的战斗是全自动的**（自动选招、自动选目标、倒下自动换人），玩家没有任何手动指令入口。所以"对战优化"实际只有四个着力点：

| 着力点 | 脚本做法 |
| --- | --- |
| 战斗倍率 | 自动 ×3（已做） |
| 全局增益 | 树果自动维持（见上，对所有战斗生效） |
| 战力 / 胜率 | 面板实时显示「均级 · 存活 · 胜率」，低于阈值告警 |
| 关键战前提醒 | 节点是道馆且存活 ≤ 一半时，优先告警而不是等翻车 |

**没有自动做的事，以及原因**：

- **自动调整队伍顺序**：游戏里"谁先上场"靠拖拽排序，脚本改它等于替你改配置；而且战斗是自动换人的，顺序只影响吃伤害的顺序，收益不稳定，风险却高。
- **自动换队员**：同样是改你的队伍配置，还可能把正在练的宝可梦换掉。
- **自动降章节刷级**：翻车时回退章节确实能保收益，但会改变你的进度，只做提示不自动执行。

## 三·八、能不能突破 ×3 速度上限

**结论：不能。** 四条路我都试过，全部被封死。

游戏里的速度判定：

```js
const va = /^(localhost|127\.0\.0\.1)$/.test(location.hostname);
const cn = i => CONFIG.SPEED_PACE?.[i] ?? i;          // 4 → 2.5
function Ya(i = state) {
  const h = +i?.speed || 1;
  return cn(va || SPEEDS.includes(h) ? Math.max(1, h)
           : Math.max(1, ...SPEEDS.filter(s => s <= h)));   // 非 localhost 一律折回 4
}
```

| 尝试 | 结果 |
| --- | --- |
| 改存档 `adv.speed = 8` | 被 `Ya()` 折回 4 → 2.5x |
| 改 `CONFIG.SPEEDS` / `SPEED_PACE` | `__seal()` 里 `Se()` 做了**深度冻结**，写入无效 |
| 伪装 `location.hostname = 'localhost'`（这条路在源码里是官方给本地开发的加速后门，能让 speed 取任意值） | `Location.hostname` 是 `[Unforgeable]`：原型上 `defineProperty` 静默无效，实例上直接抛 `Cannot redefine property` |
| 劫持 `Date.now` + `performance.now`（让游戏时间走快） | 实测**推进 0 秒**：`Clock` 每 5 秒拿服务器 `Date` 头校准，`at()` 算出偏移后把 `N` 抵消掉，时间被锁死 |
| 伪造 `lastTick` 触发离线补偿（4 小时） | 实测只补了 25 秒：启动时云存档把本地 `lastTick` 覆盖回当前 |
| 找全局 API 直接改状态 | `__seal()` 只是把模块属性改成不可配置 getter **锁死**，并不挂到 `window` 上；`window.Game` 实测是 `undefined` |

所以 **2.5x（界面显示 ×3）就是硬上限**。剩下能做的只有"别让实际倍率掉下来"：

- 新增 **实际倍率** 读数：`速度 ×3 · 实际 2.4x`，实时用「游戏内时间推进 ÷ 真实时间」算出来；
- 实际倍率低于 1.8 且持续时告警，原因通常是页面在后台、或设备渲染跟不上（特效太多）。

> 若你确实愿意承担风险硬要走"伪造离线 + 屏蔽云同步"那条路：本地存档会和云端冲突，下次正常联网时游戏按"游玩时间最长"挑选，很可能把你的进度回滚。不建议。

## 三·九、多玩法与数据透视（v3.x）

这一批需求涉及 12 个子功能，我按"能不能拿到数据 / 能不能验证"逐个过了一遍，结论如下。

### 已实现

| 功能 | 实现 |
| --- | --- |
| **宠物 S/A/B/C 评分角标** | 内嵌 493 条种族值表，按 `data-uid` 反查存档，注入绝对定位角标。队伍、PC、培育屋列表全部覆盖，`MutationObserver` 跟随重渲染。`title` 里给出六维种族值与按游戏公式估算的总属性 |
| **道馆 / 四天王死磕** | 读 `adv.deaths` 增量统计失败次数，连败 ≥3 触发告警；失败后强制确保速度档位正常、继续推进 |
| **残血自动换人** | 读 `#team-rail` 每行的 `.tr-hp i` 宽度，当前上场低于阈值时派出血量最健康的队友。**默认关闭**（会覆盖你的手动操作） |
| **游戏城无人值守** | 接管游戏自带的 `.cs-auto` 自动摇杆，附带金钱下限保护（低于阈值自动停） |

### 做不了 / 需要条件的

| 功能 | 结论 |
| --- | --- |
| **昼夜天气全图巡航** | 数据不可得。游戏把 `ENCOUNTERS` / `CONDITIONAL_WILD` 锁在闭包里，不暴露给页面；UI 上只能读到**当前路线**的「此处出没」。要比较其他路线，只能先切过去——而章节切换会重置当前节点进度。可行版本是"当前路线是否命中"的提示，不是自动巡航 |
| **培育屋流水线** | 需要百变怪才会产蛋，且寄放靠拖拽。当前存档里没有百变怪，写出来也无法验证，暂不实现 |
| **自动孵蛋** | 同上（孵化器依赖培育屋产蛋） |
| **地下洞窟** | 未解锁（需通关丰缘联盟），且是小游戏 Canvas，无法验证 |
| **团体战 Raids** | 未解锁 |
| **对战塔 Battle Tower** | 未解锁 |
| **黑市狙击** | 未解锁（侧栏还是"??????"） |
| **交换挂单自动续期** | 界面已解锁，技术上可做，需要下一步摸清挂单列表与过期态 DOM 后再实现 |

> 未解锁的四个模块我都没有硬写"猜出来的选择器"——那种代码上线后 90% 是错的，还会误点。

## 三·十一、队伍分析与配队推荐（v3.6.0）

挂机挂久了会发现：真正拖速度的不是点击，是**队伍打不动当前区域**。队伍一次上 6 只，游戏自动按速度决定先后手、按属性倍率结算伤害，带错了属性就会反复失败、复活、重走，捕获/时直接腰斩。这一版把"该带谁"算出来了。

### 数据从哪来

不是猜的，全部从游戏自己的打包代码里抠出来，写死在脚本里（离线可用，不发任何请求）：

### 评分怎么算

直接套游戏里的伤害公式（`app.js` 的 `dmg()`），不是自造的启发式：

```
伤害 = ((2×等级/5 + 2) × 威力 × 攻击 / 防御 / 50 + 2)
      × 本系加成 1.5 × 属性倍率 × 等级差修正 1.06^n × 暴击期望
```

在此基础上换算成三个可读指标：

- **输出** = 对当前区域敌人的**一击 KO 率**（按出现权重加权）
- **耐久** = **能扛住 3 回合**的敌人比例
- **先手** = 速度高于对手的概率

综合分 = 输出 45% + 耐久 30% + 先手 15% + 属性优势 10%，再折算成 S/A/B/C/D。

### 面板里能看到什么

点 HUD 上的 **「配队」** 按钮：

- **当前区域**：右侧「此处出没」解析出的敌人清单 + 每种属性（含出现权重）
- **推荐队 N 分 · 克制覆盖 X%**：从你**全部**宝可梦（队伍 + 电脑箱子）里选出的最优 6 只（不足 6 只就全上），括号里是当前队伍得分，方便对比
- **每只的明细**：Lv、属性、角色定位（坦克 / 输出 / 先手）、输出/耐久/先手、**主攻技能**（中文名 + 属性 + 威力 + 是否克制）、被谁抗
- **值得培养**：不在推荐阵容里、但种族值和成长空间最好的几只 —— 挂机时顺手练它们
- **下一道馆**：馆主、属性、等级区间、队伍成员 —— 提前知道该准备什么属性

### 「高亮推荐」做了什么

只在你已有的宝可梦格子上打黄色序号（1 = 优先上阵），**不会替你换队伍**。原因很实在：游戏的队伍编辑是拖拽 + 弹窗确认，自动操作一旦点错就是放生/替换，风险远大于收益。序号标好后你手动拖 6 下就行。

### 自动提醒

默认开启（设置里可关）。每 60 秒算一次，满足以下条件才在日志里提示一次，冷却 10 分钟：

- 当前队伍比最优解低 **12 分以上**，且比上次提示时还差了 5 分以上
- 换了区域会重置冷却（新区域新敌人，值得重新评估）

提示长这样：`配队建议：当前队伍 45 分，本区域最优 78 分，可换上 小拉达（95 分 S）。点 HUD「配队」查看。`

### 已知边界

1. **技能表是"升到该等级能学会"的技能**，不是存档里记的实际招式。游戏存档只存等级，招式由等级推导，所以这里推出来的和游戏内一致。
2. **不自动改队伍**（见上）。
3. 敌人池依赖右侧「此处出没」面板；面板没渲染时会退回按徽章等级区间估算。

## 三·十、文件管理与版本约定

这一节是为了避免多个副本互相覆盖。

| 路径 | 角色 | 说明 |
| --- | --- | --- |
| `pokecatch-autofarm.user.js`（仓库根） | **唯一真源** | 一切修改都在这里改；Tampermonkey 里安装的也是它 |
| `pokecatch/pokecatch-helper.user.js` | 镜像副本 | 只由 `sync.sh` 写入，**不要单独编辑** |
| `pokecatch/archive/*.user.js` | 历史归档 | 每次大改前的快照，只读 |
| `pokecatch/app.js` 等 | 逆向分析产物 | 游戏打包代码、探测脚本、截图，与运行无关 |

工作流：

```bash
# 1. 改：只改根目录的 pokecatch-autofarm.user.js
# 2. 同步：把改动推给镜像副本并校验 md5
./sync.sh

# 3. 安装：Tampermonkey 里覆盖粘贴根目录那份
```

如果你在 Tampermonkey 编辑器里直接改（很常见），记得**改完把内容回存到根目录的 `pokecatch-autofarm.user.js`**，再跑一次 `./sync.sh`。否则下次我基于根目录改动，就会盖掉你的编辑——这正是之前 3.3.0 撞车的成因。

> 归档约定：我来改之前，会先把当前真源复制到 `pokecatch/archive/pokecatch-<版本>.user.js` 再动手，确保任何一版都能回滚。

## 四、已知限制（都是游戏/浏览器本身决定的）

1. **后台标签会暂停**：游戏主循环里 `if (document.hidden) await visibilitychange`，切到别的标签页游戏就停。脚本只能提醒 + 保持屏幕常亮，不能绕过（伪造 `document.hidden` 会被浏览器的定时器节流反噬，收益为负）。
   → 建议：单独开一个窗口放游戏，或用「保持屏幕常亮」+ 副屏挂机。
2. **速度上限 ×3（实际 2.5x）**：游戏 `SPEEDS = [1,2,4]`、`SPEED_PACE = {4: 2.5}`，非 localhost 会把 speed 折回合法档；`CONFIG` 被深度冻结、`Location.hostname` 不可重定义、时钟劫持被服务器校时抵消。详见「三·八」。
3. **反作弊面**：游戏内置 `Game.S.patched`，会检测 `Date.now / setTimeout / requestAnimationFrame / performance.now` 是否被改写。所以本脚本**不劫持任何原生计时器、不改系统时间、不改存档数值**，只做"合法的点击代理"。
4. **多标签互斥**：游戏有 `TabLock`，同时开两个标签会互相踢。挂机时只留一个游戏标签。
5. **无法识别的弹窗**：只有一种情况不会自动处理 —— 全新类型的决策弹窗。此时面板会显示"需手动点击"并响提示音，点掉它挂机自动恢复。

## 五、还能继续加的（当前版本未做，按收益排序）

1. **自动买糖 + 喂糖**：钱多了自动在商店买经验糖 S 并喂给队伍最低等级成员。收益明确，但要处理"训练"页的拖拽/选择流程，容易误操作，建议做成手动一键。
2. **培育屋自动化**：自动寄放 → 收蛋 → 孵蛋（蛋的闪光率 1/1024，是野生的 4 倍）。需要 PC 里有可用宝可梦，逻辑分支多。
3. **自动地下通道挖矿 / 游戏城老虎机**：都是独立小游戏，各自有完整交互流程，工作量大。
4. **团体战 / 对战塔自动编排**：涉及队伍编辑与失败判定，误操作风险高。
5. **捕获策略自动切换**：按 `目标=新图鉴/缺失形态/全部` 自动切换，配合图鉴完成度。
